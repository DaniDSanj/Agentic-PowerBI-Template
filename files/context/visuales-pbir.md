# Objetos visuales (PBIR) y custom visuals

- Cambios batch por script (ej. `isHiddenInViewMode=true` en filtros) o copiar/pegar carpetas de visual/página entre reports; siempre validados contra el `$schema` de PBIR antes de darlos por buenos.
- Qué rompe el informe: violar el schema (error bloqueante, Desktop no abre), IDs duplicados, referencias a campos inexistentes. Los visuales no tienen `displayName`: identifícalos por `visualType`/`position`/`title`.
- Antes de proponer un custom visual nuevo, evalúa alternativas sin desarrollo: visuales nativos + formato avanzado, SVG en medidas DAX, o **Deneb** (Vega/Vega-Lite, MIT, certificado por Microsoft, renderiza sin dependencias externas) — hay plantillas comunitarias de referencia (David Bacci, jack-bryde, avatorl).
- Si un custom visual es imprescindible, usa `pbiviz`/`powerbi-visuals-tools` (open source, npm): `npm install -g powerbi-visuals-tools`, `pbiviz new`, `pbiviz start`, `pbiviz package`; TypeScript + D3, `capabilities.json` define dataRoles y dataViewMappings. La certificación y publicación en AppSource son pasos guiados por el usuario, no automatizables por el agente.

**Confirmado en dogfooding real** (repo `Sandbox-Agentic-PowerBI`, PR #3, primera vez que se crea un `visual.json` en todo el dogfooding — la página llevaba en blanco desde el scaffold inicial): no existe un repositorio oficial de Microsoft con ejemplos PBIR de `visual.json` fácilmente indexado (el buscador de código de `microsoft/powerbi-desktop-samples` no expone resultados sin sesión de GitHub); la estructura real se obtuvo con `gh search code "clusteredColumnChart" filename:visual.json` contra repos públicos reales — el propio `microsoft/BCApps` tiene decenas de `visual.json` de producción PBIR y fue la referencia más fiable encontrada. Un `visualContainer` mínimo válido es `{$schema, name, position:{x,y,z,height,width,tabOrder}, visual:{visualType, query:{queryState:{<rol>:{projections:[{field:{Measure|Column:{Expression:{SourceRef:{Entity}}, Property}}, queryRef, nativeQueryRef}]}}}}}` — un `cardVisual` usa el rol `Data`, un `clusteredColumnChart` usa `Category`/`Y`. Se construyeron dos visuales reales (tarjeta `Total Ventas`, `clusteredColumnChart` `Margen Bruto %` por `Segment`) y ambos abrieron limpios en Power BI Desktop.

Se provocó a propósito un ID de visual duplicado (mismo campo interno `"name"` en dos `visual.json` de la misma página, con carpetas contenedoras distintas): el hook `post-edit-pbir.ps1` **no lo detectó** (exit 0) porque valida un fichero a la vez, sin comparar contra el resto de la página — confirma que el "qué rompe el informe" de este documento (IDs duplicados) depende enteramente de invocar `pbir-schema-validator` explícitamente, el hook por sí solo no basta. `pbir-schema-validator`, invocado de verdad, sí lo marcó bloqueante correctamente.
